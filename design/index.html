The Air Shaft

“The universe (which others call the Library) is composed of an indefinite and perhaps infinite number of hexagonal galleries, with vast air shafts between, surrounded by very low railings.”Jorge Luis Borges, The Library of Babel

The screen looks straight down one of those air shafts. Every floor is a folder. The next floor’s name flickers through every possibility until the computer opens one; as you drop through it, the name falls into the path bar. At the bottom, always just out of reach, floats the book: the one file in every folder, whose contents are the path you took.

The keys type into the screen, as the Cardputer’s own keyboard would: letters look a file up, del goes back a folder, enter reads the file, tab returns to the root.

    Reading the screen

    Four folders deep into “Hello”, waiting for the host to open the fifth.

    1. Wordmark. USB OF BABEL is the MTP friendly name from DEV_INFO_MODEL. The shaft in the gallery icon lights when a host is attached.
    2. Session and activity LED. MTP while a session is open. The LED flashes crimson on every MTP operation, like a thumb drive.
    3. Lamps. “There are two, transversally placed, in each hexagon.” They sit on opposite corners of every railing and ignite floor by floor when a host connects.
    4. The next folder. The tab on the next railing cycles through every possible name. When the host opens one it locks white, the shaft drops a floor, and the name falls into the path.
    5. The file. The book at the bottom of every folder. Reading it raises the book and opens it: bytes on the left page, text on the right.
    6. Call number. The current path, newest folder last. The cursor marks where the next name will land.
    7. Title. The file at this depth, as text. Bytes that can’t be printed show as dots.
    8. Depth and size. Folders deep, and bytes in the file.

    Six states

    Each one maps to something the stick actually sees over USB, so the screen never shows a state the firmware can’t know about.

    The system

    Palette · 16 colours, 4 bits

    The frame is a 4-bit canvas, so every pixel on screen is literally one hex digit. Colours are snapped to RGB565 so this page matches the panel.

    Material ramps

    All shading is ordered 4×4 Bayer dithering along these ramps. Each passes through the cool neutrals before reaching its own hue, so whatever the lamps miss falls back to blue-black. The diamond marks the material’s true colour.

    Type

    A 5×7 face on a 6×9 cell for everything you read: 0.74 mm tall on the real panel. A 3×5 face only for units. Both are hand-set bitmaps that port to C as-is.

    Geometry

    • Vanishing point at (120, 52), set high so the shaft clears the catalog card that starts at y = 111.
    • Ring radius = 140 px ÷ depth. A long lens: texels stay near 2 px at the screen edge instead of smearing into blocks.
    • The next floor rests at depth 3.3, which puts its name tab at y ≈ 88, one clean step above the path bar.
    • Floors are 48 texels tall: railing, slab, then five shelves (“five long shelves per side”). The top and bottom walls are the story’s two free sides, dark hallways that keep text legible.
    • The IMU tilts the view: the vanishing point drifts ±6 px and rolls ±2°, the HUD stays fixed to the glass.

    Wiring it to babel-usb

    Every state is driven by a handler that already exists in src/monolith/usb_mtp_impl.c.h. The handlers run on the TinyUSB task, so they should only post an event; a display task owns the canvas.

    // usb_mtp_impl.c.h — one line per hook
static int32_t fs_open_close_session(...) {
  ...
  screen_post(OPEN_SESSION ? EV_CONNECT : EV_DISCONNECT);
}

static int32_t fs_get_object_handles(...) {
  if (parent_handle == 0xFFFFFFFF)
    screen_post(EV_ROOT);
  else if (prev_parent_handle != parent_handle)
    screen_post(EV_ENTER, (parent_handle - 1) % handle_count + 1);
  ...
}

static int32_t fs_get_object(...) {
  if (cb_data->phase == MTP_PHASE_COMMAND)
    screen_post(EV_OPEN, output_file_len);
  ...
}

    Budget on the ESP32-S3

    • Frame: 4-bit M5Canvas, 240×135 = 16,200 bytes, pushed through a 16-entry RGB565 palette.
    • Shaft: one pass over 32,400 pixels: three dot products, one divide and two table reads each. No per-pixel trig, no lookup table for the projection.
    • Tables: 20 wall textures with 5 mip levels and three light maps, generated from this file as const arrays in flash.
    • Panel: a full 16-bit frame over SPI at 40 MHz takes about 13 ms, so 30 fps leaves room for rendering.
    • Encoding: Babel-70 contents come from output_file, which the repo already maintains in fs_append_output(); Hex mode is the path itself.
